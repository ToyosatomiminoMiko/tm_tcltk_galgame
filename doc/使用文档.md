## 1. 项目简介

这是一个用 Tcl/Tk 编写的小型 Galgame(视觉小说)运行时.它做了两层拆分.

第一层是**运行时与内容的拆分**:

- **运行时**由 `main.tcl` 与 `src/` 组成,只负责解析清单,执行剧本,绘制画面,
  读写存档,里面没有任何具体作品的标题,地名,剧本或图片.
- **内容包**是 `games/<名称>/` 下的一个目录,包含 `game.tcl` 清单,`*.gal`
  剧本与 `assets/` 素材.它可以整体复制,搬走,或拆成独立仓库;运行时用
  `--game <目录>` 指过去就能运行.

第二层是**运行时内部的拆分**:剧本,状态,表现层,输入控制,存档各自独立,
可以单独替换或扩展.

项目特点:

- 内容与运行时分离:换一个 `--game` 就是换一个游戏,运行时不改一行代码.
- 剧本采用独立的 `.gal` 文本格式,不写代码也能编排剧情;可以拆成多份,用
  `include` 拼成同一条指令流.
- 界面由 Tk 原生组件构成,不依赖第三方 UI 库.
- 视觉层按内容包 `assets/` 下的约定路径找图,把图片放进去即生效;找不到时
  退化为色块,所以没有素材的内容包也能跑.
- 音频层可插拔:有 Snack 扩展时播放真实音频,没有时自动降级.
- 存档,读档,自动播放,快进,历史记录,设置等常见 Galgame 功能齐全.
- 存档属于用户数据,默认放在用户数据目录,与运行时目录,内容包目录都分开.

## 2. 环境要求与安装

### 2.1 需要什么

- Tcl/Tk 8.6 或更高版本(本项目在 Tcl 9.0.2 / Tk 9.0.2 下验证通过).
- 图形界面环境(Windows / macOS / Linux 桌面均可).
- 可选:Snack 音频扩展,用于播放真实的音乐与音效.

### 2.2 安装 Tcl/Tk

#### Linux(Debian / Ubuntu)

```bash
sudo apt install tcl tk
```

#### Linux(Fedora / RHEL 系)

```bash
sudo dnf install tcl tk
```

#### macOS(使用 Homebrew)

```bash
brew install tcl-tk
```

安装后 `wish` 可能叫 `wish8.6` 或位于 Homebrew 的 bin 目录,请按实际路径调用.

#### Windows

从 Tcl/Tk 官网安装 ActiveTcl 或 Tcl 官方发行版,安装完成后在命令行使用
`wish.exe main.tcl` 运行.

### 2.3 验证安装

```bash
wish
```

能打开一个空白窗口即说明安装成功.也可以查看版本:

```bash
wish <<'EOF'
puts "Tcl [info patchlevel] / Tk [package require Tk]"
exit
EOF
```

## 3. 运行与验证

### 3.1 正常启动

在仓库根目录(即 `main.tcl` 所在目录)执行:

```bash
wish main.tcl
```

不指定内容包时,运行时按下面的顺序挑一个:

1. `--game <目录>` 或环境变量 `GALGAME_PACK`;
2. `games/sample`;
3. `games/` 下唯一的内容包(有多个时必须显式指定).

运行别的内容包:

```bash
wish main.tcl --game games/my_game
wish main.tcl games/my_game            # 位置参数等价写法
wish main.tcl --game /path/to/pack     # 内容包可以在这个仓库外面
```

也可以使用项目自带的启动脚本(它先把工作目录切到自己所在目录,再把参数原样转发):

```bash
sh run.sh
sh run.sh --game games/my_game
```

> 注意:`run.sh` 目前没有可执行权限,直接用 `./run.sh` 会提示权限不足,
> 请使用 `sh run.sh`.

由于 `main.tcl` 内部会基于脚本自身位置计算运行时根目录,所以从其他目录用绝对
路径启动也可以:

```bash
wish /path/to/project/main.tcl --game /path/to/pack
```

### 3.2 查看与排查

列出运行时 `games/` 下所有内容包:

```bash
wish main.tcl --list-games
```

查看全部命令行选项与环境变量:

```bash
wish main.tcl --help
```

内容包清单写错(例如 `entry` 指到不存在的文件)会在启动时直接报出可读错误,
而不是等玩到一半才失败.

### 3.3 验证模式(冒烟测试)

不想打开窗口,只想确认代码能正常加载时:

```bash
wish main.tcl --smoke
```

该模式会隐藏窗口,运行约 1 秒后自动退出,用于验证所有模块可以加载.

验证内容包与剧情脚本也能正常执行:

```bash
wish main.tcl --smoke-story
```

该模式会隐藏窗口,自动开始新游戏,运行约 2.2 秒后自动退出.

两种模式都以退出码 0 表示成功.

## 4. 游戏内操作

### 4.1 标题屏

启动后首先看到标题屏,包含五个按钮:

| 按钮 | 作用 |
| --- | --- |
| 开始游戏 | 从头读取并播放当前内容包清单里的 `entry`(示例为 `games/sample/story/main.gal`) |
| 继续游戏 | 读取最近一次存档;没有存档时等同开始新游戏 |
| 读取存档 | 打开存档槽位窗口,选择要读取的档 |
| 设置 | 打开设置窗口 |
| 退出 | 关闭游戏 |

### 4.2 游戏进行中

#### 推进对话

- 鼠标左键点击画面,对话框或文本框.
- 按空格键或回车键.

台词采用逐字显示动画:第一次点击会立刻显示完整台词,再点一次推进到下一句.

#### 选项分支

遇到 `menu` 时屏幕中央会弹出选项按钮,用鼠标点击选择,点击后自动跳转到对应剧情.

#### 顶部工具栏

游戏过程中窗口顶部始终有七个按钮:

| 按钮 | 作用 |
| --- | --- |
| 自动 | 开启/关闭自动播放,按设定间隔自动推进对话 |
| 快进 | 开启/关闭快进,以更短间隔跳过对话 |
| 历史 | 打开对话记录窗口,查看最近 300 条台词 |
| 存档 | 打开存档槽位窗口,保存当前进度 |
| 读档 | 打开读档槽位窗口 |
| 设置 | 打开设置窗口 |
| 标题 | 停止当前游戏并返回标题屏 |

自动播放和快进互斥:开启其中一个会自动关闭另一个.

### 4.3 设置窗口

可调整以下项目:

| 设置项 | 说明 |
| --- | --- |
| 文字速度 | 每个字的显示间隔,5–100 毫秒,数字越小越快 |
| 自动播放间隔 | 自动播放时两句之间的间隔,500–5000 毫秒 |
| 音效 | 勾选后播放音效(无音频后端时退化为系统提示音) |
| 音乐 | 勾选后允许播放背景音乐 |
| 全屏 | 勾选后切换全屏显示 |

点击"应用"生效,"取消"关闭窗口且不生效.

> 注意:设置只保存在内存中,退出程序后恢复默认值,不会写入磁盘.

### 4.4 存档与读档

- 共 6 个存档槽位,保存在"存档根目录/内容包 id/"下;默认的存档根目录见
  [第 8 节](#8-存档位置与格式),可以用 `--saves <目录>` 或 `$GALGAME_SAVE_DIR` 改动.
- 存档会记录:内容包 id,剧本相对内容包目录的路径,指令位置,剧情旗标,背景,
  CG,登场角色,对话历史(最近 30 条)以及是否处于等待状态.
- 读档时空槽位会被拦截并提示.
- 存档属于另一个内容包,或者格式过旧时,读档会给出明确提示而不是直接崩溃.
- 读档后如果存档时正处于选项界面,会恢复选项;如果正在显示台词,会恢复该句.

## 5. 目录结构与内容包

```text
.
├── main.tcl                # 入口:加载模块, 解析参数, 定位内容包, 创建应用
├── run.sh                  # 启动脚本(切到脚本目录后把参数转发给 main.tcl)
├── src/                    # 运行时: 不含任何具体作品的信息
│   ├── pack.tcl            # 内容包清单解析, 路径 / 素材 / 存档目录解析
│   ├── config.tcl          # 运行时配置项(内存字典)
│   ├── state.tcl           # 游戏运行时状态
│   ├── script.tcl          # 剧本 DSL 解析器(支持 include 拼接多份 *.gal)
│   ├── audio.tcl           # 音频后端接口(Snack / 降级)
│   ├── visual.tcl          # Canvas 背景 / CG / 立绘绘制与缩放缓存
│   ├── save.tcl            # 存档 / 读档
│   ├── log.tcl             # 对话记录窗口
│   ├── dialogs.tcl         # 设置窗口与存档槽位窗口
│   ├── ui.tcl              # 主界面,文字框,选项框,标题屏
│   ├── engine.tcl          # 命令执行与流程控制
│   └── application.tcl     # 应用装配与自动 / 快进逻辑
├── games/                  # 内容包: 可以整体复制, 搬走或独立成仓库
│   ├── README.md           # 内容包格式与新建方式
│   └── sample/             # 示例内容包
│       ├── game.tcl        # 清单: 标题 / 起始剧本 / 素材目录 / 地点名 / 窗口尺寸
│       ├── story/
│       │   ├── main.gal    # 起始剧本(清单的 entry 指向它)
│       │   └── endings.gal # 由 main.gal 用 include 拼进来
│       └── assets/         # 素材: 兜底图 + bg/ cg/ characters/ 约定目录
├── doc/                    # 文档
└── README.md               # 项目简介
```

存档不在上面这棵树里:它默认写在用户数据目录的 `galgame/<内容包 id>/` 下,
见 [第 8 节](#8-存档位置与格式).

### 5.1 运行时与内容包的边界

| 东西 | 放在哪 | 谁提供 |
| --- | --- | --- |
| 模块加载, 参数解析, 事件循环, 各子系统 | `main.tcl`, `src/` | 运行时 |
| 窗口标题, 副标题, 窗口尺寸 | 清单 `game.tcl` | 内容包 |
| 起始剧本, 剧本之间的 `include` | 清单 `entry`, `story/*.gal` | 内容包 |
| 素材目录与兜底图片 | 清单 `assets`, `defaults` | 内容包 |
| 地点名(顶栏显示的文字) | 清单 `locations` | 内容包 |
| 素材按 id 的查找约定 | `src/pack.tcl` | 运行时 |
| 存档根目录与按 id 分层 | `src/pack.tcl`, `main.tcl` | 运行时 |
| 存档内容本身 | 用户数据目录 | 运行时写, 属于用户 |

判断标准很简单:换一个游戏就要改的东西属于内容包,换游戏不用改的东西属于运行时.

### 5.2 内容包清单 game.tcl

清单是普通 Tcl 脚本,`source` 的返回值就是清单字典,约定写成一条 `return {...}`.
因为清单会被 `source` 执行,所以不要运行来源不可信的内容包.

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `id` | 目录名 | 内容包标识;存档按它分目录 |
| `title` | `id` | 窗口标题与标题屏主标题 |
| `subtitle` | 空 | 标题屏副标题,为空时不显示 |
| `entry` | `story/main.gal` | 起始剧本,相对内容包目录 |
| `assets` | `assets` | 素材目录,相对内容包目录 |
| `defaults` | 见下表 | 兜底图片,相对 `assets` |
| `locations` | 空 | 背景 id 到地点显示名的映射 |
| `geometry` | `960x640` | 主窗口初始尺寸 |
| `minsize` | `{800 560}` | 主窗口最小尺寸 |

`defaults` 是一个小字典:

```tcl
defaults {
    background "default_background-image.png"   # 背景 / CG 的兜底图
    figure     "default_figure-image.png"       # 立绘的兜底图
}
```

`entry` 与 `assets` 必须是相对路径,而且不能指到内容包外面:这样整个内容包才能
随意搬家(相对路径解析与越界检查都在 `src/pack.tcl`).

加载内容包时会立即校验:`entry` 指向的文件必须存在,`assets` 目录必须存在,
否则启动时报错并给出完整路径.

### 5.3 新建一个内容包

最省事的方式是复制示例包再改:

```bash
cp -r games/sample games/my_game
$EDITOR games/my_game/game.tcl        # 至少改 id 与 title
$EDITOR games/my_game/story/main.gal  # 换成自己的剧情
wish main.tcl --game games/my_game
```

素材按约定丢进 `assets/`:

| 文件 | 用途 |
| --- | --- |
| `bg/<id>.png` | `bg <id>` 的背景图 |
| `cg/<id>.png` | `cg <id>` 的 CG |
| `characters/<角色>_<表情>.png` | `show <角色> <表情>` 的立绘 |
| `default_background-image.png` | 上面三类找不到时的背景兜底图 |
| `default_figure-image.png` | 立绘找不到时的兜底图 |

图片缺失不会报错,会退化成色块,因此内容包可以一开始只有剧本.

## 6. 剧本编写指南

### 6.1 基本规则

剧本是纯文本文件,按行解析,每行一条命令.规则如下:

- `#` 开头(或行内未加引号处的 `#`)为注释,解析时会被去掉.
- 行首和行尾的空白会被忽略,缩进仅用于可读性.
- 空行会被跳过.
- 字符串用英文双引号 `"..."` 包裹,内部可以包含中文和空格.
- 引号内的 `#`,空格都是普通字符,不会按注释或分隔符处理.
- 反斜杠 `\` 可以转义引号内的字符.
- 命令与参数之间用空格分隔;没有用引号包裹的多个词会被拆成多个参数.

示例:

```text
# 这一行是注释
say "Alice" "她说:#这不是注释"   # 行尾注释
```

### 6.2 命令参考

#### 流程控制

| 命令 | 语法 | 说明 |
| --- | --- | --- |
| `label` | `label <名称>` | 定义一个跳转点,名称全局唯一 |
| `jump` | `jump <标签>` | 无条件跳到指定标签 |
| `if` | `if <旗标> -> <标签>` | 旗标为真时跳转 |
| `if` | `if <旗标> <运算符> <值> -> <标签>` | 比较后跳转,支持 `== != < > <= >=` |
| `ifnot` | `ifnot <旗标> -> <标签>` | 旗标为假时跳转,也可带比较 |
| `menu` | `menu` | 开始选项块 |
| `option` | `option "<文字>" <标签>` | 选项文字与跳转目标 |
| `endmenu` | `endmenu` | 结束选项块 |
| `include` | `include "<文件>"` | 拼接另一份剧本,路径相对当前文件所在目录 |
| `wait` | `wait <毫秒>` | 等待指定毫秒后继续 |
| `end` | `end` | 结束剧情,返回标题屏 |
| `title` | `title "<标题>"` | 设置剧本元信息标题(可选;窗口标题以内容包清单为准) |

> **场景边界**:进入任意 `label` 时,运行时会丢弃上一个场景的表现数据
> (背景,CG,全部立绘,待选选项,逐字动画与未触发的 `wait` 定时器),
> 因此 `jump` / `if` / 选项跳转后不会残留上一个场景的角色.
> **旗标不会在场景边界被清空**,否则跨场景的分支判断会失效;
> 它们只在"开始新游戏"或"读档"时重置.
> 推论:靠 `jump` 进入的 label 如果仍要显示上一场景的背景或立绘,
> 必须在该 label 内重新写 `bg` / `show`(示例剧本中每个 label 都自己声明).

> **多份剧本**:`include` 在**解析期**展开,被拼进来的文件与主文件共享同一条
> 指令流和同一份标签表:所以 `jump` 可以跨文件跳到后面文件里的 `label`,
> `label` 不能重名(重名直接报错),一个 `menu` 块必须完整写在同一个文件里,
> `include` 也不允许成环.引擎与存档格式都只看到展开后的线性指令流,不需要
> 知道剧本被拆成了几份.

#### 视觉

| 命令 | 语法 | 说明 |
| --- | --- | --- |
| `bg` | `bg <id>` | 切换背景,同时清空 CG |
| `cg` | `cg <id>` | 切换 CG(覆盖背景) |
| `show` | `show <角色> <表情> [left\|center\|right]` | 显示立绘,默认居中 |
| `hide` | `hide <角色>` | 隐藏立绘 |

`show` 的第三个参数支持 `left`,`center`,`right`,缺省为 `center`.
表情目前支持 `normal`,`smile`,`blush`,`sad`,其它值按默认表情绘制.

当前版本中,`bg` 和 `cg` 都绘制同一张默认背景图,`show` 的所有角色共用
同一张默认立绘图,仅按站位(left / center / right)放置.

#### 文字

| 命令 | 语法 | 说明 |
| --- | --- | --- |
| `say` | `say "<角色名>" "<台词>"` | 显示一句带名字的对白 |
| `narrate` | `narrate "<旁白>"` | 显示一句旁白(不显示说话人) |

#### 旗标(变量)

| 命令 | 语法 | 说明 |
| --- | --- | --- |
| `flag` | `flag <名称> <值>` | 设置旗标的值 |
| `clear` | `clear <名称>` | 删除旗标 |
| `add` | `add <名称> <数值>` | 对旗标做数值累加(非数字按 0 处理) |

旗标用于记录分支状态.判断真假的规则:

- 空值,`false`,`0` 视为假;
- `true`,非零数字视为真;
- 其它非空字符串一律视为真.

比较时如果两边都是数字就按数值比较,否则按字符串比较.

#### 音频

| 命令 | 语法 | 说明 |
| --- | --- | --- |
| `music` | `music <id>` | 播放背景音乐(编号会被记录,供音频后端使用) |
| `stopmusic` | `stopmusic` | 停止背景音乐 |
| `sfx` | `sfx <id>` | 播放一次音效 |

没有 Snack 扩展时,音效会退化为系统提示音,音乐只记录编号不发声.

### 6.3 完整示例讲解

下面是 `games/sample/story/main.gal` 的核心片段逐行解释:

```text
# 标题不写在这里: 窗口标题与标题屏文案来自内容包清单 game.tcl

# 定义剧情起点
label start
bg classroom                 # 切换到教室背景
show alice normal center     # 让Alice以普通表情站在中间
say "Alice" "啊,你还没走?太好了."
narrate "夕阳把教室染成暖橙色,Alice从窗边转过身来."

# 出现三个选项
menu
option "陪她去图书馆" library
option "去天台吹风" rooftop
option "今天想直接回家" home
endmenu

# 每个选项跳到对应标签
label library
bg library
flag went_library 1          # 记录选择了图书馆路线
add affection 1              # 好感度 +1
jump evening                 # 三条路线汇合

label evening
bg sunset
if went_library -> library_ending   # 根据旗标进入不同结局
if went_rooftop -> rooftop_ending
if went_home -> home_ending
jump library_ending

# 结局标签写在另一个文件里, 在这里拼进同一条指令流
include "endings.gal"
```

三个结局标签(`library_ending`,`rooftop_ending`,`home_ending`)都在
`games/sample/story/endings.gal` 里,由最后那行 `include` 拼接进来:
`include` 的路径相对**当前文件所在目录**解析,所以把 `story/` 目录整体搬走
也依然成立.

### 6.4 常见剧本错误

| 错误 | 提示 |
| --- | --- |
| 引用了不存在的标签 | `Unknown label: xxx` |
| 命令名写错 | `Unknown story command: xxx` |
| 参数数量不对 | 各命令有独立的参数数量检查,如 `say requires <name> <text>` |
| `menu` 块缺少 `endmenu` | `menu block is missing endmenu` |
| 在 `menu` 块内写了非 `option` 命令 | `only option/endmenu allowed inside menu block` |

| `include` 的文件不存在 | `文件:行号: include 的文件不存在: 完整路径` |
| `include` 成环 | `include 成环: 路径 (调用链: a -> b -> a)` |
| `label` 重名 | `文件:行号: label 重复定义: 名称` |
| 内容包清单写错 | 启动时输出 `内容包错误: ...`,并以退出码 2 结束 |

修改剧本后,需要回到标题屏重新"开始游戏"才会重新解析剧本.

## 7. 系统架构

### 7.1 模块职责

| 模块 | 职责 |
| --- | --- |
| `main.tcl` | 入口:定位运行时自身,按固定顺序加载模块,解析命令行,定位内容包,创建 `Application` |
| `pack.tcl` | 内容包层:`GamePack` 类,清单解析,素材查找,内容包发现,存档目录解析 |
| `config.tcl` | `Config` 类:运行时配置的读写与布尔开关 |
| `state.tcl` | `GameState` 类:剧情指针,旗标,历史,背景,角色等运行时数据 |
| `script.tcl` | 剧本解析:`Story` 类,注释剥离,词法切分,标签索引,`include` 展开 |
| `engine.tcl` | `Engine` 类:逐条执行指令,分支跳转,等待与菜单控制 |
| `ui.tcl` | `UI` 类:主窗口,标题屏,对话框,逐字动画,选项框,按键绑定 |
| `visual.tcl` | `Visual` 类:向内容包索取素材路径,在 Canvas 上绘制并缓存缩放图 |
| `audio.tcl` | `Audio` 类:音乐与音效接口,Snack 缺失时降级 |
| `save.tcl` | `SaveManager` 类:存档目录,序列化,读档,槽位摘要 |
| `log.tcl` | `LogWindow` 类:独立的对话历史窗口 |
| `dialogs.tcl` | `ConfigDialog` 与 `SlotDialog`:设置窗口,存档槽位窗口 |
| `application.tcl` | `Application` 类:接收内容包与存档目录,装配全部子系统,提供高层操作 |

### 7.2 启动流程

1. `main.tcl` 创建 `galgame` 命名空间,记录运行时根目录与源码目录 `src/`.
2. 按固定顺序 `source` 加载各模块:内容包层最先,应用装配最后.
3. 解析命令行;`--help` 与 `--list-games` 只依赖运行时,到此就结束.
4. 定位内容包目录,`source` 它的 `game.tcl` 清单并构造 `GamePack`;清单有问题
   会在这里报错并以退出码 2 结束.
5. 按内容包 id 解析存档目录,创建 `Application`;它内部依次创建 `Config`,
   `GameState`,`Audio`,`UI`,`SaveManager`,`LogWindow`,`Engine`,其中
   `UI` 与 `Visual` 都会拿到内容包对象.
6. 根据命令行参数进入 `run`(正常游戏),`smoke` 或 `smoke_story`.
7. `run` 显示主窗口,展示标题屏,然后进入 Tcl 事件循环(`vwait`).

### 7.3 剧情执行流程

`Engine` 是流程控制核心:

1. `start` 把指令指针归零,进入 `run_loop`.
2. `run_loop` 逐条读取指令并交给 `dispatch` 分发.
3. 每条指令返回"继续"或"暂停":`bg`,`flag`,`jump` 等立即继续;
   `say`,`narrate`,`menu`,`wait` 会进入等待状态.
4. 玩家点击或定时器到时后,通过 `advance`,`choose`,`resume_after_wait`
   恢复执行.
5. 执行到 `end` 或超出剧本末尾时,调用 `return_title` 返回标题屏.

### 7.4 事件循环与异步

- `after` 用于逐字动画,自动播放,快进和 `wait` 命令的定时调度.
- `vwait` 保持主循环运行,程序不会在界面弹出后退出.
- 所有异步任务都保存了任务编号,停止模式或清空台词时会用 `after cancel` 取消;
  `wait` 的任务编号由引擎保存,返回标题屏,读档,选择选项或玩家点击推进时
  都会先取消它,避免剧情在标题屏背后继续执行.

### 7.5 内存与场景生命周期

运行时把数据分成三类,清理时机不同:

| 数据 | 生命周期 | 说明 |
| --- | --- | --- |
| 旗标(flags) | 一局 | 跨场景的分支依据,只在开始新游戏/读档时重置 |
| 场景表现(背景/CG/立绘/选项) | 一个场景 | 进入新 `label` 时清空,不留上一个场景的残留 |
| 对话日志(history) | 一局(日志) | 供"历史"窗口查看,返回标题屏后仍保留,开新游戏时清空 |

其他资源:

- 剧情对象 `Story`:开始新游戏或读档时会先销毁上一个对象再解析新剧本.
  写成 `oo::class` 的对象不会因为失去引用而自动回收,必须显式 `destroy`,
  否则每次开始游戏都会把整份解析结果留在内存里.
- 设置窗口与存档槽位窗口:关闭(应用/取消/点右上角关闭)时销毁窗口并销毁
  对应的对象;窗口已经打开时再次点击只会把它置前,不会重复创建.
- 选项按钮:选项被选中后会立即销毁,不留在内存里等下一次菜单.
- 缩放后的图片:缓存键是"源文件路径 + 目标尺寸 + 缩放模式",只跟画布尺寸有关;
  窗口尺寸变化时整批丢弃重建,与场景切换无关.源图解码完就释放,不进缓存,
  所以一张很大的背景不会因为显示过就一直占着内存.
- 内容包对象与其清单:每个进程只加载一个内容包,生命周期等于进程,不涉及回收.

## 8. 存档位置与格式

### 8.1 放在哪里

存档是用户数据,既不属于运行时也不属于内容包,所以默认不写在仓库里.
存档根目录按下面的优先级确定:

1. 命令行 `--saves <目录>`;
2. 环境变量 `$GALGAME_SAVE_DIR`(别名 `$GALGAME_DATA_DIR`);
3. `$XDG_DATA_HOME/galgame`;
4. `$HOME/.local/share/galgame`;
5. 以上都没有时,退回当前目录下的 `saves/`.

每个内容包在根目录下再占一层以清单 `id` 命名的子目录:

```text
<存档根目录>/<内容包 id>/slot01.save ... slot06.save
```

例如默认情况下,示例内容包(`id` 为 `sample`)的存档在 `~/.local/share/galgame/sample/`
下.想把它放回仓库里的 `saves/`:

```bash
wish main.tcl --saves ./saves
GALGAME_SAVE_DIR=./saves wish main.tcl
```

### 8.2 文件格式

格式为 UTF-8 文本,每行 `字段 值`,其中值用 Base64 编码,避免特殊字符破坏
行式格式:

```text
galgame_save 2
saved_at <时间(Base64)>
pack <内容包 id(Base64)>
script <相对内容包目录的剧本路径(Base64)>
ip <指令位置(Base64)>
waiting <等待状态(Base64)>
bg <背景编号(Base64)>
cg <CG编号(Base64)>
characters <角色字典(Base64)>
pending <待选选项(Base64)>
flag <旗标名(Base64)> <旗标值(Base64)>
history <最近30条历史(Base64)>
```

第一行 `galgame_save 2` 是格式标识与版本:

- 版本 1 存的是剧本的**绝对路径**,内容包一换目录就失效,已不再支持;
  读到版本 1 会提示格式不受支持.
- 版本 2 起存**内容包 id + 相对路径**,读档时用当前内容包的目录去拼,
  所以内容包整体搬走以后老存档依旧有效.
- 读档时会核对 `pack`:拿别的内容包的存档来读会明确报错,而不是恢复出一堆
  对不上的跳转.

## 9. 扩展指南

### 9.1 使用与替换图片素材

按 id 找图的约定已经实现,不需要改代码:把图片放进内容包的 `assets/` 即可生效.

- 背景:先找 `assets/bg/<id>.png`,找不到就用清单 `defaults.background`
  指定的兜底图,再找不到就画色块;
- CG:先找 `assets/cg/<id>.png`,同样回落到兜底图;
- 立绘:先找 `assets/characters/<角色>_<表情>.png`,回落到清单
  `defaults.figure` 指定的兜底立绘.

兜底图的文件名写在清单里,所以换一套占位图不用动代码:

```tcl
defaults {
    background "default_background-image.png"
    figure     "default_figure-image.png"
}
```

素材 id 只允许是不含路径成分的名字(`..` 与 `/` 会被拒绝),避免剧本里写错的
id 让运行时去读内容包外面的文件;这条检查在 `src/pack.tcl` 的 `safe_asset_id`.

如果要加"按 pose 做变换""淡入淡出转场"这类效果,改 `src/visual.tcl`:
它负责解码,缩放,绘制与缓存,`src/pack.tcl` 只负责告诉它文件在哪.

### 9.2 接入音频后端

`src/audio.tcl` 的 `Audio` 类封装了 `play_music`,`stop_music`,`play_sfx`,
`click` 四个接口.当前实现优先使用 Snack,缺失时降级.可以:

- 安装 `snack` 扩展(Tcl 包),让现有代码直接播放;
- 或替换为 VLC,SDL 等后端,只需保持这四个方法签名不变.

接真实音频时,`music` / `sfx` 命令里的 id 来自内容包,文件应放在内容包的素材
目录下(具体子目录与命名可以沿用 `bg` / `cg` / `characters` 的做法,在
`src/pack.tcl` 里加一个查找方法即可).可以把 `GamePack` 对象传给 `Audio`,
让它和视觉层一样"只问路径,不猜位置".

### 9.3 新增剧本命令

两步即可新增一条命令:

1. 如果命令需要特殊解析(如 `menu` 块,`include`),在 `src/script.tcl` 的
   `Story::load_file` 中处理;普通命令会原样进入指令列表,无需改动.
2. 在 `src/engine.tcl` 的 `dispatch` 中增加分支,执行后返回 `1`(继续)
   或 `0`(暂停等待).

### 9.4 扩展存档内容

在 `src/state.tcl` 增加新的状态字段后:

- 在 `src/save.tcl` 的 `save` 方法中把新字段写入文件;
- 在 `load` 方法的字段白名单中加上新字段并恢复;
- 在 `src/application.tcl` 的 `load_slot` 中把新字段写回状态对象.

如果新增字段会让旧存档无法正确恢复,就把 `$galgame::SAVE_VERSION` 加一:
旧存档会被明确判为"格式不受支持",而不是恢复出一半的状态.存档里的 `pack`
与 `script` 两个字段是内容包解耦的关键,不要改回绝对路径.

### 9.5 自定义界面

界面组件集中在 `src/ui.tcl`.标题屏,顶栏,对话框,选项框都有独立的构建方法,
可以直接修改组件布局或主题色.需要注意的是标题,副标题,窗口尺寸与地点名都来自
内容包清单,界面代码只负责显示;主窗口配色,字号等仍在这里集中配置.

### 9.6 再做一层:把内容包放到另一个仓库

运行时只依赖清单字段,不依赖内容包放在哪里,所以可以:

- 把 `games/my_game/` 整个复制到一个独立仓库;
- 用 `wish /path/to/runtime/main.tcl --game /path/to/my_game` 运行;
- 或者设 `GALGAME_PACK=/path/to/my_game`,再直接 `wish /path/to/runtime/main.tcl`.

内容包的作者只需要看 `games/README.md` 与 `games/sample/game.tcl`,完全不必读
`src/`.

## 10. Tcl/Tk 基础与注释规则

### 10.1 Tcl 是什么

Tcl 是一种解释型脚本语言,一切操作都是"命令 + 参数":

```tcl
命令 参数1 参数2 ...
```

命令之间用换行或分号 `;` 分隔.例如:

```tcl
set name "Alice"
puts "你好, $name"
set sum [expr {1 + 2}]
```

要点:

- `$变量名` 取变量值;
- `[命令]` 把命令的返回值插入当前位置;
- `"..."` 内部会做变量与命令替换;
- `{...}` 是字面量,内部不做替换,常用于传代码块或列表.

### 10.2 Tk 是什么

Tk 是 Tcl 的图形界面工具包,`wish` 是同时带有 Tcl 与 Tk 的解释器.创建界面就是
"创建组件 + 布局 + 绑定事件":

```tcl
button .hello -text "你好" -command {puts "点击了"}
pack .hello
```

常用组件: `button`,`label`,`entry`,`text`,`canvas`,`frame`,`ttk::*`.
布局用 `pack` 或 `grid`,事件用 `bind` 和 `-command` 回调,定时任务用 `after`,
事件循环用 `vwait` 或 Tk 自带的循环.

### 10.3 Tcl/Tk 的注释规则

#### 行首注释

以 `#` 开头的行是注释,整行都会被忽略:

```tcl
# 这是注释
# 这也是注释
```

#### 行内注释

Tcl 中注释只在"命令起始位置"才被识别.如果想把注释写在命令后面,必须先加分号:

```tcl
set x 1;  # 这是行内注释
```

不加分号会出错或产生歧义:

```tcl
set x 1 # 这不是注释(会被当成多余参数)
```

#### 引号与花括号内的 `#` 是普通字符

```tcl
set s "#不是注释"      ;# 双引号内的 # 是普通字符
set s {#也不是注释}    ;# 花括号内的 # 是普通字符
```

#### 多行(块)注释

Tcl 没有原生块注释,常用"永远不会执行的条件"来模拟:

```tcl
if 0 {
    这段内容不会被执行,
    相当于多行注释.
}
```

注意花括号必须配对,内容里不能出现未配对的 `}`.

#### 剧本 DSL 中的注释

本项目 `.gal` 剧本的注释比 Tcl 更宽松:解析器会在引号和花括号之外找到 `#` 时
直接截断该行,因此行内注释不需要分号:

```text
flag went_library 1   # 记录路线
say "Alice" "#这句话里带井号"   # 引号内的 # 不是注释
```

### 10.4 本项目源码的注释规范

源码里大量使用中文注释,阅读时注意这几种位置:

1. **文件头注释**:每个 `.tcl` 文件第一段 `#` 说明该模块的职责.
2. **类与变量注释**:`oo::class` 里的 `variable` 声明上方或右侧解释每个变量用途.
3. **方法注释**:方法定义上方说明它做什么,何时被调用.
4. **行内注释**:解释较复杂的逻辑,例如"等待状态""任务编号".

示例(来自 `main.tcl`):

```tcl
#!/usr/bin/env wish
# 上述行指定使用 wish 解释器(Tk 的图形界面 shell),用于启动 GUI 应用程序.
# Galgame 运行时入口.
# [职责边界] 本文件只做运行时该做的事: 定位自己, 加载 src/ 下的模块, 解析命令行,
# 找到内容包并启动. 任何具体作品的信息(标题/剧本/素材/地点名)都不在这里, 而是
# 在内容包目录的 game.tcl 清单里, 见 src/pack.tcl.
namespace eval galgame {}

# 运行时根目录: 基于本脚本自身位置计算, 因此可以从任意目录用绝对路径启动.
set ::galgame::ROOT [file normalize [file dirname [info script]]]
```

读代码的顺序建议:

1. `main.tcl`:了解入口,参数与环境变量;
2. `src/pack.tcl`:了解"运行时与内容"的边界(清单字段,素材查找,存档目录);
3. `application.tcl`:了解各子系统如何装配,按钮回调到哪里;
4. `engine.tcl`:了解剧情指令如何执行;
5. 其余模块按需阅读.

## 11. 常见问题

### 已知问题

### 提示 `wish: command not found`

没有安装 Tcl/Tk,请参考 [第 2 节](#2-环境要求与安装)安装.

### 运行 `./run.sh` 提示权限不足

启动脚本没有可执行权限,改用 `sh run.sh` 或 `wish main.tcl`.

#### 启动时报 `没有找到内容包` 或 `不是内容包(缺少 game.tcl)`

运行时没有在 `games/` 下找到可用内容包,或者 `--game` 指的目录里没有
`game.tcl`.用 `wish main.tcl --list-games` 看看有哪些内容包,再用
`--game <目录>` 显式指定;`games/` 下有多个内容包时必须显式指定.

#### 启动时报内容包清单字段错误

清单里的 `entry` 必须是存在且位于内容包目录内的文件,`assets` 必须是存在且
位于内容包目录内的目录,两者都只能用相对路径.报错信息里会给出完整路径.

#### 没有声音

当前音频后端优先使用 Snack 扩展.未安装 Snack 时,音效会退化为系统提示音,
背景音乐只记录编号不发声.安装 Snack 或按 [9.2 节](#92-接入音频后端)接入其它后端即可.

#### 设置保存后重启又变回默认

这是当前设计:设置只存在内存中,不会写盘.

#### 改了剧本但没有变化

剧本在"开始游戏"时才重新加载,请返回标题屏后重新开始游戏.

#### 改了清单里的标题,但窗口标题没变

清单在启动时读取一次,请重新启动程序.

#### 存档文件在哪

在"存档根目录/内容包 id/"下,共 6 个槽位,文件名为 `slot01.save` 至
`slot06.save`.默认的存档根目录是 `~/.local/share/galgame`,可以用
`--saves <目录>` 或 `$GALGAME_SAVE_DIR` 改动;完整规则见
[第 8 节](#8-存档位置与格式).

#### 内容包能放到这个仓库外面吗

能.运行时不关心内容包的绝对位置,只按清单字段取用:

```bash
wish main.tcl --game /path/to/my_game
```

也可以把内容包做成独立仓库,只把 `games/` 整个目录搬走.

#### 无图形界面(纯服务器)环境能运行吗

直接运行会因没有显示服务器而失败.可以借助虚拟显示(如 `xvfb-run`)运行冒烟测试:

```bash
xvfb-run wish main.tcl --smoke
```

#### 中文乱码或字体难看

请确认系统安装了中文字体;剧本和源码均为 UTF-8 编码,请勿用非 UTF-8 编辑器修改.

---

本运行时的设计目标是小而清晰.它有两层边界:

- 外面一层是运行时与内容:运行时只认清单,内容包可以随意复制,搬走,独立成仓库;
- 里面一层是运行时内部的剧本,状态,界面,视觉,音频,存档,各自独立.

因此它既适合作为 Tcl/Tk 学习的示例,也适合在此基础上扩展成完整的视觉小说引擎.
